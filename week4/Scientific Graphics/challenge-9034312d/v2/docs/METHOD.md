# 方法与设计 · Method

## 1. 问题
科研图稿的失败很少是"画不出来"，而是**画得像却不可核对**：实体张冠李戴、抑制画成激活、上下游颠倒、出现材料里没有的数值、图例与数据分类对不上、交付物只有位图。通用绘图工具与通用 Agent 都把图当成图像生成任务，缺少"图是科学陈述"的约束。

## 2. 做法：把图拆成三层可核对的中间表示
```
材料 (PDF/CSV/XLSX/DOCX)  →  证据表 evidence   →  图稿规格 spec (实体-关系-编码)  →  显示列表  →  SVG/PDF/PNG/TIFF
        ↑ 逐字引文+定位            ↑ 每个元素绑定引文            ↑ 同一份几何驱动两个渲染器
```
* **证据层**：抽取正文与表格，保留页码/表行定位；每个实体、关系、图表绑定一条逐字引文。
* **规格层**：`spec.json` 描述实体、关系类型与方向、包含关系、区室、数据映射、图例、画布与导出参数。规格是唯一事实来源，渲染器不发明内容。
* **渲染层**：布局引擎把规格算成毫米级几何（分层、蛇形/纵列/分栏、包含框、绕障走线、标签避让），再由 SVG 写入器与 matplotlib 渲染器**消费同一份显示列表**，保证矢量源文件与导出件一致。

## 3. 相对通用方案的关键改进
| 通用做法 | 本方案 | 可检验的差别 |
|---|---|---|
| 直接生成图片或一张 SVG 字符串 | 规格→几何→双渲染器 | 改一个标签只改 spec，重跑得到同一张图；SVG 与 PDF 几何同源 |
| 箭头统一画成箭头 | 关系类型驱动终点形状（箭头/横杠/菱形） | 抑制不会被画成激活；`SEM-RELATION-WORD` 还能用引文动词反查类型错误 |
| 图例手写 | 图例项数与数据分类数比对 | `LEG-MATCHES-DATA` 直接拦住"图例 4 项、数据 3 类" |
| 数值手打 | 数值只能来自数据表，柱高/点位置由表计算 | `NUM-TRACEABLE` 拒绝材料中不存在的数字 |
| 位图截图交付 | 分层 SVG（`layer-*` 组、活文字、`data-src`）+ 内嵌字体的矢量 PDF + 600 dpi PNG/TIFF | 文字可选中、可替换字体、可按元素追溯来源 |
| 一次性出图 | 25 项自检 + 修复建议 + 状态降级 | 失败可见：`status=partial` 且 `limits[]` 写明原因 |

## 4. 为什么这样更省人力
一次出图的时间主要花在"找依据—搭结构—改细节"三件事上。规格层把"搭结构"变成填 JSON，把"改细节"变成改 JSON 后重跑（秒级），把"找依据"变成必须填的引文（否则自检失败）。人工返工从"重画整张图"降为"改一行规格"；同一份规格可换画布预设、换字体、换导出格式而不动内容。

## 5. 边界（本方案不做什么）
* 不做统计方法选择与显著性计算：显著性标记只按规格绘制，`p` 值与检验方法必须来自材料，否则写入 `uncertainty`。
* 不做艺术插画、海报版式与照片美化；图元是几何形状与文字，不生成位图素材。
* 不做论文正文写作与文献综述。
* 不"补全"材料中没有的实体、浓度、时间点或单位：缺就是缺，写入 `uncertainty` 与 `limits`。
* 自动布局面向 5–40 个元素的机制图/流程图/示意图；上百节点的网络图需要分层子图或外部布局坐标。

## 6. 可复现性
* 同一 `spec.json` + 同一字体环境 → 同一 SVG（逐字节稳定）与同一 PDF 几何。
* `result.json` 记录输入 `sha256`、规格、检查结果、导出参数与运行时长；`figure_provenance.csv` 可按元素复核。
* 评测环境的字体差异会改变文字宽度估计与换行；`GLYPH-CJK` 与 `export_report.fonts_missing` 会暴露这一点。
