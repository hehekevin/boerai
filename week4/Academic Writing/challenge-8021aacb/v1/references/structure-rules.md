# 结构诊断规则（structure-rules.md）

## 1. 诊断四问

- 诊得准：定位到章节+段落+原句摘录；归类为五型之一（问题-贡献对齐/章节顺序/论证链/重复衔接/结论边界）。
- 改得动：动作必须是可执行编辑——MOVE(段A→§X后)、MERGE(段A+段B)、SPLIT(段A于句S处)、NARROW(句S收窄为…)、ADD-TRANSITION(段A与B间)、ADD-HEADING。
- 链得通：研究问题在引言被明确提出、方法覆盖问题所需、结果回应方法、结论只综合结果——闭环断裂处点名缺环。
- 说得清：每条诊断带依据（原文引用 + 为什么是问题）。

## 2. 五型问题清单

| 型 | 典型信号 | 动作 |
|-|-|-|
| 问题-贡献对齐 | 贡献主张含方法未覆盖的内容 | NARROW 贡献句 |
| 章节顺序 | 铺垫后置/细节前置/两节交叉 | MOVE |
| 论证链 | "因此/表明"句无行内证据；结论引用了未报告的数据 | ADD-EVIDENCE / NARROW |
| 重复衔接 | dup 检测命中（overlap >= 0.4）；段间无过渡 | MERGE / ADD-TRANSITION |
| 结论边界 | 结论含数据范围外的普适表述；缺限制说明 | NARROW / ADD-LIMITATION |

## 3. dup 判读

- overlap >= 0.6：强重复（几乎同义）→ MERGE 建议；
- 0.4–0.6：疑似（引用性重复/固定术语短语）→ 人工确认；
- 引文块、方法惯用句的重复标 false-positive，不进 actions。

## 4. 结论边界检查

结论句逐一比对数据范围（样本/条件/时长）：出现"普遍/所有/证明"而数据是单条件小样本 → NARROW；缺局限说明 → ADD-LIMITATION（落到具体失效场景，不写套话）。

## 5. 输出纪律

- 每条诊断 = 位置 + 类型 + 依据原文 + 动作 + 参数，五件套缺一不发。
- 不给"建议加强论证"这类不可执行表述。

## 6. 异常处置

| 情形 | 处置 |
|-|-|
| 无标题稿 | 段落群诊断 + ADD-HEADING 建议 |
| dup 误报 | 人工确认 false-positive |
| 底稿为摘录 | 诊断限给定文本 + gaps |
| 预算不足 | 三个 JSON 先落盘，诊断 partial |
